# OpenWorld included Claude beta - October 31

This candidate preserves free play and existing Sonnet BYOK with 16,000 output tokens and images. It adds a text-only Haiku 5.5 allowance through the shared persistent budget gateway. The feature flag remains OFF and production is unchanged. No direct owner-key fallback, automatic provider retry, new account, credential, resource, email or live model request was used in this preparation.

## Accepted profile and costs

The tracked game is 739,349 bytes, or 627,340 after existing optimization, plus a 14,179-byte system prompt. About 214,000 input tokens at three characters per token is only an estimate, not a billed count. The existing agent makes one non-streaming Messages request with six recent messages and the current game/request, without tools or schema, then uses its bounded SEARCH/REPLACE parser, opaque sandbox and private versions.

Root accepted input up to 768 KiB and 8,000 output tokens, text only, two attempts per actor and four per network in a rolling 24-hour window. OpenWorld has a $25 rolling 30-day allocation within central $150 serving / $200 outer caps. Shared availability is not guaranteed. The gateway must count, reserve and settle centrally; unknown outcomes retain their reservation and the UUID cannot issue another provider call.

Official pages opened October 31: [Haiku 5.5](https://platform.claude.com/docs/en/models/haiku-5-5/overview) lists prompts over 100,000 tokens at $0.50/M input and $2.50/M output, with shorter prompts at $0.10/$0.50. [Sonnet 5.5](https://platform.claude.com/docs/en/models/sonnet-5-5/overview) is $2/$10. Actual costs vary; no per-creation fixed price is promised. The chosen included profile is cheaper, while existing optional BYOK retains its model/output/image behavior.

## Authority, persistence and privacy

Actors come from authenticated accounts or the existing cryptographic guest capability, so the first bounded demo needs no signup. Server HMACs of actor and network go to the gateway; raw account IDs, guest proofs and IPs do not. The network ceiling uses public Railway ingress X-Real-IP only on the canonical public host, with IP validation and IPv6 /64 grouping; internal/noncanonical hosts cannot fund creations. [Railway technical specifications](https://docs.railway.com/networking/public-networking/specs-and-limits) and its [staff clarification](https://station.railway.com/questions/need-authoritative-client-ip-proxy-tru-090eac86) were read; these are current ingress behavior, not a permanent platform guarantee.

The local SQLite request table binds UUID, actor and payload hash, reserves allowances atomically across workers, retains unknown outcomes and replays completed private versions without another gateway call. Only explicit dispatched:false proof for a certain pre-dispatch code releases the actor allowance; unknown or contradictory flags hold it. The independent network ceiling still counts submitted attempts, bounding repeated refusal storage. HTTP status alone never refunds it. A funded job owns its DB session and finishes independently of browser waiting. A closed private session cannot be recreated by a late included result. Existing account export/deletion, contact and recovery behavior stays accepted. Operational request hashes/references have no automatic expiry and privacy says so.

The shared gateway uses purpose-separated Ed25519 signing from the existing stable JWT_SECRET via HKDF-SHA256 with empty salt and purpose portfolio-claude/v1/openworld. Only the derived public SPKI is saved in qa/claude-beta-public-key.txt. No private derived key is saved or sent. Node independently verifies the exact Python signature/HKDF contract in the source tests. Existing production secret was checked only for presence/length/64-hex shape. Neither ANTHROPIC_API_KEY nor ANTHROPIC_AUTH_TOKEN exists in this app environment; no organization GET was made without a key.

The gateway stores permanent budget/idempotency metadata, never raw prompts in DB/logs. Successful response text is encrypted for recovery for up to one hour; ciphertext deletion is opportunistic. This is access expiry, not a cryptographic-erasure or backup-deletion guarantee. The gateway worker confirmed that narrower wording. New Privacy/Terms and UI accurately distinguish included processing, optional BYOK billing, rolling allowances, shared capacity and unknown outcomes.

## Acceptance and remaining rollout

Current 15 focused cases pass, and the actual local 375/1440 functional UI passes. The full pre-correction run passed 58 of 59 and found the fixed late-closure case; no final whole-suite green result is claimed. Follow-up transport and refusal/network quota checks pass. The final bounded UI run uses the corrected backend. [Acceptance](../qa/claude-beta/acceptance.md) separates the UI run from final backend lifetime correction and preserves exact limits of the proof. Provider and game fixtures are explicitly synthetic; they cannot establish Claude quality or genuine gateway receipt. The existing real game acceptance is preserved. Root owns central spend/credit provenance, complete metering/stopping of every owned path, public-key pin and gateway GO. Until then this candidate is not deployed or enabled. The first real evaluation must be one simple small-game modification with source parser/sandbox validation, followed by exact public changed-flow acceptance.
